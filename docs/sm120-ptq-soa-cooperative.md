This user-authorized private fork starts at `b3735a7de8df0aba4e0ab1915acfb5e1f9f18e19`, retaining its llama.cpp/ggml and Prism source attribution and licenses. This slice has no build, numerical, launch, performance, memory, quality or adoption acceptance yet.

Only the process-cached literal `GGML_CUDA_PTQ1_0_SOA_COOPERATIVE=1` requests the new plain kernel. Unset, empty,0,01,1x and other values use existing routes. No request metadata establishes execution. The gate requires runtime and highest-compiled sm120, PTQ1_0/Q8 SoA exact-isum N1, exact K5120, M>=64, W4/L32, no IDs/fusion, one input/activation/output channel and sample, native packed row stride, contiguous output, and32-byte-aligned weight/activation/output bases. Other inputs retain their existing selected paths.

Each physical warp owns one output row and an896-byte shared tile containing32 native28-byte blocks. Four warps allocate3584 bytes. Seven warp-contiguous32-bit load groups copy qs[24], qh[2] and d[2] without decoding, repacking or changing scale bits. K5120 has40 blocks: the second tile reads exactly224 bytes/56 words, with no row-end overread. Only its eight valid logical lanes decode. M row tails are uniform within each warp and skip input/output access.

The existing dot helper is unchanged. Each logical lane keeps blocks l,l+32 and the stock per-lane accumulation and XOR reduction order. Full-warp fences publish the tile and prevent overwrite before all consumers finish. PDL entry, native launcher/stream and return completion match the stock small-K path; local aliases use the native GGML_CUDA_RESTRICT boundary. There is no CTA barrier, asynchronous pipeline, persistent weight copy, global allocation or tensor-pool change.

The hypothesis is improved load request grouping, not fewer logical packed bytes or proven DRAM traffic. Stock loads are aligned, and successive accesses can reuse L1/L2 sectors; added shared stores/loads and warp fences can lose. No speed, occupancy, energy or ZBook result follows from the source. The transferable ThunderKittens idea is bounded cooperative loading with explicit tile ownership; no TK code, dependency, producer warp, TMA, WGMMA or TCGen05 is imported.
